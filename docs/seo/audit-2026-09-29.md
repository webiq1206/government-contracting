# Public site audit: SEO, answer engines, conversion

Date: September 29, 2026. Scope: every indexable page on brostco.com (32 URLs
in the sitemap), the crawl surface (robots.txt, sitemap.xml, llms.txt, feed),
and the trial signup journey. Branch `claude/website-seo-aeo-geo-cro-d3y3ax`.

This file records what was measured, what was changed and why, what could not
be done from here, and how to compare later. Outcomes (rankings, citations,
clicks, trials) are not claimed anywhere in it: they need a recrawl and weeks
of data.

## 2. Changes made, with the reason for each

Technical (T)

- T1. `middleware.ts`: permanent redirect from any `www.` host to the apex,
  preserving path and query. Removes the duplicate host. Tested.
- T2. `lib/domain/public-routes.ts`: named AI crawlers extended to the
  tokens each vendor now documents (Claude-SearchBot, Claude-User,
  Perplexity-User, DuckAssistBot, Applebot, Amazonbot, meta-externalagent).
  The wildcard rule already allowed them, but a named allow removes
  ambiguity for crawlers that treat an unnamed wildcard cautiously. Robots
  remains an allow list of the public surface plus the private prefixes.
- T3. `app/sitemap.ts`: `lastmod` emitted only where a page carries a real
  editorial date (guides: the hand-check date shown on the page; register:
  its most recent `verifiedOn`; tools and sector pages: the day their
  content last changed). Pages without such a date still omit it rather
  than pretending.
- T4. Wordmark served through `next/image` with intrinsic dimensions (696x159
  and 699x160), so the browser gets a copy sized for 28 px in a modern
  format and reserves the space before it arrives.

Structured data (S)

- S1. New `lib/marketing/schema.ts`: one Organization node with a stable
  `@id` (`/#organization`), legal name, wordmark logo (696x159; the square
  mark is 109 px wide, under the 112 px minimum), support email and a
  description. Every page that names BrostCo as author, publisher or creator
  now references that identifier instead of repeating a loose object.
- S2. Home page: the four separate scripts are one `@graph`. WebSite gains
  `alternateName: ["Brost Co"]` and a publisher reference; SoftwareApplication
  gains a `featureList` drawn from the visible page copy and a publisher
  reference. FAQPage is kept: Google withdrew FAQ rich results in May 2026,
  but the markup remains valid, matches the visible questions word for word,
  and is read by answer engines. No ratings or reviews are claimed.
- S3. `PageIntro` now emits a BreadcrumbList matching the breadcrumb it
  already displays, on all 13 pages that use it. Tool and sector pages show
  and mark up a three-level trail (Home / Free tools / tool; Home /
  Opportunity sources / sector).
- S4. Guides: Article gains `datePublished` and `dateModified` from constants
  that also drive the visible "Published ... Source links checked ..." line,
  plus `image`, `inLanguage` and the shared organization reference.
- S5. Register: Dataset gains `datePublished`, `license` (the page's own
  Reuse and citation section), `keywords`, `variableMeasured` and the
  shared creator/publisher reference. Tool pages: WebApplication gains
  `isAccessibleForFree`, `browserRequirements` and the shared publisher.

Entity and naming (E)

- E1. "BrostCo" is now the name on llms.txt (which also states the "Brost
  Co" spelling once, deliberately), the web app manifest, the four sitemap
  summaries, the privacy and terms descriptions and the wordmark alt text.
  Legal body text keeps "Brost Co" where the Terms define it as the
  defined term. Google's site name signals (WebSite name, og:site_name,
  title suffix) now agree.

Titles and descriptions (M)

- M1. /pricing-guide title "Pricing and service usage" became "Pricing,
  free trial and service usage costs": it names the two things people search
  for on a pricing page. Description unchanged.
- M2. /signup title "Start your BrostCo free trial | BrostCo" repeated the
  brand; now "Start your free 7-day trial | BrostCo", with its own Open
  Graph URL and description (it inherited the home page's).
- M3. Privacy and Terms descriptions rewritten to say what each page covers.
- All other titles were left alone: they are unique, descriptive and within
  a sensible length, and there is no click data to justify rewrites.

Content (C)

- C1. The three sector pages gain a "Common NAICS codes for this work"
  section: a short table of the 2022 NAICS codes and titles contractors in
  that sector most often see on federal notices, with the caution that the
  notice's own code governs and the size standard follows it, and links to
  the SAM.gov search guide and the Census Bureau NAICS lookup. This answers
  a question people actually type ("NAICS code for janitorial services
  government contracts") on pages that were otherwise templated, without
  adding pages.
- C2. "Resources" added to the primary navigation. The guides, tools,
  register and sector pages were reachable only from the footer; they now
  sit one click from every page for readers and crawlers alike.

Performance and usability (P)

- P1. Inter and Manrope self-hosted through `next/font/local` (Latin subset,
  variable weight, 48 KB and 25 KB, SIL OFL). Removes the render-blocking
  Google Fonts stylesheet and two third-party connections from every page,
  and adds a metric-matched fallback so headings do not shift when the font
  arrives. CSS points at the font variables with the named families kept as
  fallbacks.
- P2. Product-tour posters load only when a player is within 400 px of the
  viewport, and after the phone/desktop choice has been made. On the home
  page that removes roughly 1.9 MB of eager JPEG stills competing with the
  hero image, and the double download on phones.
- P3. Product-tour tab numbers darkened (#5b7f74 to #3f625a) after Lighthouse
  flagged their contrast at 11 px.

Tests updated for deliberate behaviour changes: the FAQ schema test reads a
graph; the product video test asserts the poster is absent until the player
is near; the brand type test checks the self-hosted font declarations; the
middleware test gains www-to-apex cases.

## 4. Not changed, and why

- FAQPage on /ai and /pricing-guide: no search benefit since May 2026 and the
  visible questions are already plain text for answer engines. Not added.
- Footer column headings are `<h2>`. Common pattern, no measured harm; left.
- The Clarity consent prompt covers the bottom of the first viewport until
  answered. It is a deliberate consent design (commit badb908); whether to
  keep an opt-in prompt for a US audience is the owner's call, not an audit
  fix. Flagged only.
- Home and pricing pages are `force-dynamic` (promo state, request-time
  analytics) and therefore send `no-store`, which keeps them out of the
  back/forward cache. Switching to revalidation would stop the request-time
  `landing_view` event. Left as designed.
- Product-tour JPEG posters were not re-encoded to WebP or AVIF. Lazy
  loading removed them from the critical path; re-encoding 16 stills is a
  small further saving that should be done from the original captures, not
  from the JPEGs.
- No Organization `sameAs`, `address`, `telephone` or `foundingDate`: none of
  those facts appear on the site, so none is asserted in markup.
- Google Business Profile: BrostCo is a software company with no public
  street address or service area on the site, so a Business Profile is not
  applicable unless the owner wants one. No location pages were created.
- No new pages. The two possible cannibalisation pairs (bid/no-bid guide vs
  tool, compliance matrix guide vs tool) serve different intents
  (read vs use) with distinct titles and were left as is.

## 5. Blockers and work needing access or a decision

1. Indexing is the gating problem. Google has 0 rows of search data and 0
   sitemap URLs recorded as indexed. The sitemap was resubmitted Sept 28; do
   not resubmit again. After this branch deploys, request indexing in Search
   Console for /, /resources, /tools, /contract-opportunities and
   /resources/idaho-procurement-sources by hand (the URL Inspection API
   cannot request indexing). IndexNow already covers Bing on merge to main.
2. Bing Webmaster Tools: connect an account (or grant this session one) to
   read Bing data and confirm the sitemap there.
3. Analytics: either create a GA4 property for brostco.com or rely on the
   first-party `analytics_events` table. Give the reporting run admin access
   to `/api/admin/growth` so trial starts and CTA clicks can be reported.
4. Ahrefs: the connected plan returns "Insufficient plan" for every API
   call, so keyword volumes, backlinks and rank tracking are unavailable.
5. `http://brostco.com` redirects to `https://brostco.com:443/`. Ask Replit
   support or check the deployment's custom-domain settings; nothing in the
   repository controls it.
6. Rich Results Test and Schema Markup Validator: the sandbox cannot reach
   Google's validators. JSON-LD was validated locally (parses, one graph per
   page, required properties present); run the Rich Results Test on the
   deployed URLs once live.
7. PageSpeed Insights API quota was exhausted for the shared project; run it
   on the live URLs after deploy to get field data if any exists.
